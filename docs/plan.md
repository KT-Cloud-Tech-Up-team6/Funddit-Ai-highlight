# 하이라이트 쇼츠 자동화 PoC 계획서 (보존본)

> 원 계획서에서 구현 중 확정된 개정 2건 반영:
> **개정①** M2도 시각(ms)을 직접 만들지 않는다 — `source_cue_id`만 반환, 표시 타이밍은 코드가 계산.
> **개정②** 기계 검증 가능한 체크 항목은 사람 육안이 아니라 코드 게이트(`poc/gates.py`)로 처리.

**대상**: 10분 라이브 펀딩 방송 1건
**목적**: "이게 되긴 하는가" 확인 + 쓸 모델과 대략적 비용 산정
**수준**: PoC — 정답셋·정량 채점 없음, 사람이 눈으로 판단 (주관 항목만)

## 1. 검증할 것

```
STEP 1  영상을 파트별로 자동 구분     → 되는가?
STEP 2  판매자가 그중 고름            → 고를 만하게 나오는가?
STEP 3  고른 파트로 쇼츠 자동 생성    → 손 안 대고 완성되는가?
        (컷 + 세로 크롭 + 포인트 자막)
```

| # | 확인할 것 |
| --- | --- |
| Q1 | 시연 파트·펀딩 홍보 파트를 모델이 알아서 찾아내는가 |
| Q2 | 잘린 구간이 말 중간에서 끊기지 않는가 |
| Q3 | 포인트 자막이 틀린 숫자를 말하지 않는가 |
| Q4 | 선택 후 사람 손 없이 쇼츠가 완성되는가 |
| Q5 | 어떤 모델을 쓸 것인가 |
| Q6 | 방송 1회에 대략 얼마 드는가 |

## 2. 파트 유형

| 코드 | 파트 | 판별 |
| --- | --- | --- |
| P1 | 시연 파트 | 모델 |
| P2 | 질문 집중 파트 | **코드** (댓글 수 세기 — `poc/comments.py`) |
| P3 | 펀딩 홍보 파트 (혜택·마감) | 모델 |
| P4 | 제품 스펙 파트 | 모델 |
| P5 | 제작 배경 파트 | 모델 |

## 3. 파이프라인

```
다시보기 영상 10분
   ├─ S1. STT (전체)            → 자막 텍스트 + 문장 타임코드   poc/stt_whisper.py
   ├─ M1. 구간 분할 (모델)      → 파트 유형 + cue_id 범위       poc/m1_segments.py
   │      + 댓글 수 세기(코드)  → P2 구간                       poc/comments.py
   ├─ 판매자 선택 (사람)         → 최대 3개
   ├─ M2. 포인트 자막 (모델)     → 선택 구간에만                 poc/m2_captions.py
   └─ 렌더링 (FFmpeg)           → 컷 + 세로 9:16 + 자막 번인    poc/render.py
```

모델을 고를 곳: **STT / M1 / M2** 세 군데. 프롬프트 원문은 `poc/prompts.py` (M2는 개정① 반영판).

- 전체 STT는 판단용 텍스트만 — 자막 파일로 안 만듦. 포인트 자막은 선택 구간에만.
- 상품 용어 목록은 코파일럿 상품정보 색인(`knowledge[]`)을 그대로 주입 → `data/product_terms.json` 형식.
- 시각(ms)은 M1·M2 모두 모델이 만들지 않는다 (개정①).

## 7. 렌더링 (FFmpeg)

| 작업 | 방법 |
| --- | --- |
| 컷 | 문장 경계 기준 |
| 세로 9:16 | 중앙 고정 크롭 (문제 있으면 추적 크롭 검토) |
| 포인트 자막 번인 | 하단, 반투명 배경 박스 (ASS) |
| 인코딩 | H.264 |
| 자막 시각 | 원본 기준 → **쇼츠 로컬 기준 오프셋 변환** (코드가 처리, 구현 완료) |

## 8. 비교할 모델

STT 2종:

| 후보 | 확인할 점 | 상태 |
| --- | --- | --- |
| Whisper large-v3 (로컬, M4 맥) | API 비용 0. 10분 처리 시간, 수치 인식 | 구현 완료 (`faster-whisper`) |
| Google Speech-to-Text v2 (chirp_3) | 타임코드 정밀도, 한국어 인식 | 구현 완료 (`poc/stt_google.py`, 무음 경계 55초 조각 → 동기 API, GCS 불필요) — 자격증명 필요 |

M1/M2 LLM 2종:

| 후보 | 확인할 점 |
| --- | --- |
| Gemini 3.5 Flash-Lite (`gemini-3.5-flash-lite`) | 코파일럿에서 쓰는 모델. 이걸로 충분한가 |
| Gemini 3.7 Flash | Flash-Lite로 부족할 때 |

조합: STT는 Whisper large-v3로 확정(실측 1위·비용 0원). LLM은 **Gemini 등급 간 비교**로 한정한다 — 챗 API가 Gemini라 운영을 통일하는 편이 낫다.

Vision은 일단 쓰지 않음 — 자막만으로 시연 파트를 못 찾으면 그때 검토.

## 9. 확인 방법 — 체크리스트

개정②에 따라 ⚙(코드 게이트가 자동 판정)와 👁(사람 육안)으로 구분.

### 9-1. 구간 분할 (M1)

| 확인 항목 | 판정 | 방식 |
| --- | --- | --- |
| 시연 파트를 찾아냈는가 | O/X | 👁 |
| 펀딩 홍보 파트를 찾아냈는가 | O/X | 👁 |
| 파트 유형 라벨이 내용과 맞는가 | O/△/X | 👁 |
| 구간이 말 중간에서 시작·종료하지 않는가 | O/X | 👁 (+문장 재병합으로 완화) |
| 구간 길이가 60~120초인가 | O/X | ⚙ SEG_LENGTH |
| evidence가 실제 자막에 있는 문장인가 | O/X | ⚙ SEG_EVIDENCE_FAKE |
| 없는 내용으로 구간을 만들지 않았는가 | O/X | ⚙ (cue_id·evidence 게이트) |
| 후보가 고를 만큼(4개 이상) 나왔는가 | O/X | 👁 |

### 9-2. 포인트 자막 (M2)

| 확인 항목 | 판정 | 방식 |
| --- | --- | --- |
| 자막 문구가 실제 발화에 있는 내용인가 | O/X | ⚙ CAP_SOURCE_FAKE + 👁 |
| **숫자가 틀리지 않았는가** (가격·성능) | O/X | ⚙ CAP_NUMBER_FAKE (한글 수사 대조) |
| 자막이 뜨는 타이밍이 발화와 맞는가 | O/△/X | ⚙ (코드가 큐 시각으로 계산) |
| 12자 이내로 읽기 편한가 | O/X | ⚙ CAP_TEXT_LEN + 👁 |
| 구간당 3~6개 나왔는가 | O/X | ⚙ CAP_COUNT |
| 파트에 맞는 내용인가 | O/X | 👁 |

### 9-3. 완성 쇼츠

| 확인 항목 | 판정 |
| --- | --- |
| **선택 후 손 안 대고 완성됐는가** | O/X |
| 말 중간에서 끊기지 않는가 | O/X |
| 세로 화면에서 진행자·제품이 잘리지 않는가 | O/X |
| 자막이 화면 밖으로 나가거나 겹치지 않는가 | O/X |
| **그대로 올려도 될 만한가** (팀원 3명 O/X) | O/X |

> **가장 중요한 두 가지**: ① 선택 후 손 안 대고 완성되는가 ② 숫자가 틀리지 않는가. 둘 중 하나라도 X면 그 조합은 탈락.

## 10. 비용 확인 — 방송 1회 기준 (실측으로 채울 표)

| 단계 | 호출 수 | CFG-1 | CFG-2 | CFG-3 |
| --- | --- | --- | --- | --- |
| STT (10분) | 1 | 0원 (Whisper large-v3 로컬, GTX 1080 추론 109초) | Google STT 실측 대기 | Google STT 실측 대기 |
| M1 구간 분할 | 1 | $0.0011 (Flash-Lite, 3.2초) | — | $0.0065 (Flash, 6.4초) |
| M2 포인트 자막 | 3 | $0.0009 (3×$0.0003, 1.5초/회) | — | $0.014 (3×$0.0048, 7.8초/회) |
| 렌더링 | — | 0 | 0 | 0 |
| **합계 (원/방송 1회)** | | ≈ $0.002 (3원) | STT 실측 대기 | ≈ $0.021 (30원) + STT |

별도 확인: 쇼츠 1개 추가 비용(M2 1회+렌더링) / 판매자 선택 화면까지 시간 / 선택 후 완성까지 시간 / 쇼츠 1개 파일 용량.

사전 추정치: Google STT 10분 ≈ $0.2~0.4, Flash-Lite는 이 입력량이면 수원~수십원 → **비용 지배 항목은 STT뿐**. Whisper 로컬 통과 시 방송 1회 비용 ≈ 0.

## 11. 모델 선정 기준

| 결정 | 기준 |
| --- | --- |
| STT | 숫자를 틀리게 받아쓰면 탈락. 통과하면 **비용 없는 Whisper 로컬 우선** (처리 시간이 실용 범위인 경우) |
| LLM | Flash-Lite가 체크리스트 통과하면 **Flash-Lite 확정**. 못 하면 Flash |
| Vision | 자막만으로 시연 파트를 못 찾을 때만 추가 검토 |
| 크롭 | 중앙 고정으로 진행자가 잘리면 추적 크롭 |

## 14. 예상되는 문제 → 대응

| 문제 | 대응 | 상태 |
| --- | --- | --- |
| STT가 제품명·숫자를 틀리게 받아씀 | ① 용어 목록을 STT 힌트로 주입 (Whisper initial_prompt / Google phrase boost, `--terms`) ② 후처리 치환 (`terms[].surface→canonical`) | ① 구현됨, ② 치환 코드 미구현 |
| Whisper가 무음 구간에 없는 말을 만듦 | VAD 적용 (`vad_filter=True` 기본값) | 구현됨 |
| 모델이 없는 시각을 만듦 | M1·M2 모두 cue_id만 지정 (개정①) | 구조적 차단 완료 |
| 구간이 60초 미만 | 프롬프트 규칙 3으로 확장 | Flash-Lite가 31·40초 구간 생성 — 프롬프트 보강 필요 |
| 시연 파트를 못 찾음 | 프롬프트 예시 보강 → 안 되면 Vision | — |
| 후보가 2~3개뿐 | 유형 정의 확장 or 최소 개수 조건 | — |
| 세로 크롭에서 진행자 잘림 | 추적 크롭으로 변경 | 중앙 고정만 구현 |
| STT 큐가 문장 중간에서 끊김 | `merge_to_sentences` 재병합 | 구현됨 |
| 구간 안에 긴 무발화(음악) 포함 | SEG_GAP 게이트(10초 이상 WARN) → 프롬프트에 규칙 추가 검토 | 게이트 구현, Flash P3에서 34초 갭 검출 |
| P2와 모델 구간 겹침 | M1은 P2를 모름 — 겹침 허용하고 선택 화면에서 정리 (잠정) | 미결 |
| P2 구간을 판매자가 선택 | 발화 기반 M2가 빈약할 수 있음 — PoC에선 관찰만 | 미결 |
