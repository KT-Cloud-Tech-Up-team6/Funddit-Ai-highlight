## 1. 시험 설계

### 1-1. 무엇을 측정했나

모델이 담당하는 곳은 두 군데다. 각각 다른 기준으로 채점했다.

**M1 (구간 분할)** — 20분 방송에서 쇼츠로 쓸 구간을 찾는다.

| 지표 | 정의 | 왜 중요한가 |
| --- | --- | --- |
| recall | 기대 파트(시연·홍보·스펙) 중 찾아낸 비율 | 못 찾으면 판매자가 고를 후보가 없다 |
| IoU | 찾은 구간이 기준 구간과 겹치는 정도 | 경계가 어긋나면 말이 중간에 잘린다 |
| 길이OK | 60~120초 규칙을 지킨 비율 | 쇼츠 길이가 들쭉날쭉하면 쓸 수 없다 |
| 갭없음 | 10초 이상 무발화를 포함하지 않은 비율 | 음악 구간이 끼면 쇼츠가 빈다 |
| 오탐 | 없는 파트를 지어낸 횟수 | 잘못된 후보를 보여주면 신뢰를 잃는다 |
| **안정성** | 같은 입력 3회 실행 시 같은 구간을 고르는 정도 | **매번 다른 후보를 보여주면 못 쓴다** |

M1 점수 = 0.35×recall + 0.30×IoU + 0.15×길이 + 0.10×갭 + 0.10×무오류 − 0.10×오탐

**M2 (포인트 자막)** — 선택된 구간에 띄울 자막 문구를 만든다.

| 지표 | 정의 |
| --- | --- |
| 사실커버 | 그 구간의 핵심 사실(가격·수치·혜택)을 자막이 담은 비율 |
| 개수OK | 구간당 3~6개 규칙 준수 |
| 12자OK | 문구 12자 이내 준수 |
| ERR | 숫자 환각·근거 없는 자막 수 |

M2 점수 = 0.45×사실커버 + 0.15×개수 + 0.20×12자 + 0.20×무오류

**총점** = (M1 점수 + M2 점수) ÷ 2

### 1-2. 공정성 확보

- **입력 고정**: 모든 모델이 같은 STT 자막을 받는다 (Whisper large-v3)
- **M2 입력 고정**: 구간을 모델이 고르게 두면 쉬운 구간을 고른 모델이 유리해진다. 그래서 M2는 **기준 구간을 고정**해 넣었다
- **3회 반복**: 1회만 재면 운이 섞인다
- **2개 영상 교차**: 한 영상에만 맞는 모델을 걸러낸다

### 1-3. 채점 기준을 두 번 고쳤다

**첫 번째 문제 — 기준 구간 길이가 규칙과 달랐다.**
처음 만든 기준 구간이 32~140초로 들쭉날쭉했다. 프롬프트는 60~120초를 요구하는데 기준이 43초짜리면, 규칙을 지켜 90초로 자른 모델이 IoU에서 감점된다.
실제로 3.7 Flash는 154~244초를 골랐고 기준은 154~206초였다. 내용은 맞는데 IoU 0.58로 깎였다.
→ 모든 기준 구간을 60~120초로 재작성. 재채점 결과 3.7 Flash의 IoU가 **0.43 → 0.74**로 올라 순위가 뒤집혔다.

**두 번째 문제 — 발화에 없는 값을 STT 채점에 넣었다.**
월 할부금 27,723원과 하루 925원은 화면 자막에만 나오고 진행자는 말하지 않는다. STT가 못 받아쓴 게 아니라 애초에 발화가 없다.
→ 채점 대상에서 제외. kw_score **0.89 → 1.00**.

> 재채점에는 API를 다시 부르지 않았다. 모델이 무엇을 골랐는지는 결과 JSON에 남아 있어 채점만 다시 하면 된다 (`eval/rescore.py`).

## 3. 읽어낸 것

### 3-1. Pro 등급은 답이 아니다

`gemini-3.1-pro-preview`는 비용이 **3.7 Flash의 9.6배**(254.7원 vs 26.5원)인데 총점은 더 낮다(0.87 vs 0.90).

- 로보락에서 **오탐 0.7회** — 없는 파트를 지어낸 유일한 상위 모델
- 안정성 0.55 — 3회 실행에서 절반은 다른 구간을 골랐다
- 호출당 25.6초로 가장 느리다

이 작업은 추론 난이도가 높지 않다. 자막을 읽고 구간을 나누는 일이라 상위 등급의 이점이 나타나지 않는다.

### 3-2. 최신 모델이 항상 낫지 않다

`3.8-flash`가 `3.7-flash`보다 두 영상 모두에서 낮았다(0.84 vs 0.90). 비용은 1.7배다.
로보락에서 recall 89%로 파트를 하나 놓쳤고 IoU도 0.28로 최하위권이었다.

**모델 버전 번호는 이 작업의 성능 순서와 무관하다.** 실측 없이 최신 버전을 고르면 손해다.

### 3-3. 하위 모델의 약점은 구간 길이다

`3.1-flash-lite`와 `3.5-flash-lite`는 M2(자막)에서는 상위 모델과 거의 같다(사실커버 78~83%). 문제는 M1이다.

**길이 규칙 준수율**

| 모델 | 로보락(20분) | 올리고365(7분) |
| --- | --- | --- |
| 3.1-flash-lite | 100% | **0%** |
| 3.5-flash-lite | **11%** | **17%** |

짧은 영상에서 구간을 짧게 잡는 경향이 뚜렷하다. 올리고365에서 3.1-flash-lite가 고른 구간은 전부 60초 미만이었다.

실제 선택 예시 (로보락, 3회 반복):

```
3.7-flash        run1: P3 154~244s, P1 259~346s, P4 513~613s
                 run2: P3 154~244s, P1 305~394s, P4 395~513s
                 run3: P3 154~244s, P1 310~394s, P4 513~613s
                 → 길이는 안정적(87~118초), 구간은 조금씩 이동

3.1-flash-lite   run1: P3 154~244s, P1 244~310s, P4 513~583s
                 run2: P3 154~244s, P1 244~310s, P4 513~583s
                 run3: P3 154~244s, P1 244~310s, P4 513~583s
                 → 3회 완전히 동일 (안정성 1.00), 다만 P1이 66초로 짧음

3.5-flash-lite   run1: 6개 구간 (23~52초), run2: 3개, run3: 6개
                 → 개수도 길이도 매번 다름. 23초짜리 구간은 쇼츠로 못 쓴다
```

### 3-4. 안정성은 등급과 무관하다

| 모델 | 안정성 |
| --- | --- |
| 3.1-flash-lite | **1.00** (하위 등급) |
| 3.6-flash | 0.81 |
| 3.7-flash / 3.8-flash | 0.74 |
| 3.1-pro | 0.55 (최상위 등급) |
| 3.5-flash | **0.43** |

`3.5-flash`는 로보락에서 안정성 0.20이었다. 같은 방송을 세 번 돌리면 거의 매번 다른 구간을 고른다.
판매자가 어제 본 후보를 오늘 못 찾는다면 제품으로 쓸 수 없다.

### 3-5. 숫자 환각은 0건

42회 실행, 자막 수백 개에서 **없는 숫자를 지어낸 사례는 없었다.**

M2 오류 열의 0.11~0.33은 숫자 환각이 아니라 "근거 발화를 찾을 수 없는 자막"이며, 게이트가 렌더링 전에 걸러냈다.
계획서에서 가장 중요하게 본 조건("숫자가 틀리면 그 조합은 탈락")은 **모든 모델이 통과**했다.

이는 모델이 잘해서가 아니라 **구조 덕분**이다.
- 모델은 시각(ms)을 만들지 않는다 — cue_id만 지정하고 코드가 시각을 조회한다
- 자막의 숫자는 근거 발화나 상품 용어 목록에 있어야 한다 — 코드가 대조한다
- 한글 수사도 변환해 비교한다 ("이만 파스칼" ↔ "20,000Pa")

| Gemini 3.5 Flash-Lite 오디오 | 12% | 0건 | 79초 | 8초 | 3원 |

**Whisper large-v3로 확정한다.** 모든 항목에서 1위이며 API 비용이 없다.

클라우드 STT의 문제는 **타임코드**다. 텍스트는 그럴듯한데 시각이 5~79초씩 어긋난다.
구간을 자르고 자막을 띄우는 데 시각이 쓰이므로, 타임코드가 틀리면 쇼츠가 엉뚱한 곳에서 시작한다.

`3.5-flash-lite` 오디오는 정확도 12%로 사실상 실패했다. 오디오 입력에서는 등급 차이가 텍스트보다 훨씬 크게 벌어진다.

**모든 방송이 쇼츠 소재가 되지는 않는다.**

| 영상 | 길이 | 장면 전환 | 분당 컷 | 판정 |

| 로보락 F25 (첫 영상) | 9분 20초 | 20회 | 2.1 | **부적합** |

첫 영상은 장면이 28초에 한 번 바뀐다. 30초 쇼츠를 만들면 화면이 거의 정지해 보인다.
발화만 보고 구간을 고르면 "말은 흐르는데 화면은 멈춘" 쇼츠가 나온다.

→ `poc/motion.py`를 추가해 소재 단계에서 걸러낸다. 게이트 `SEG_STILL`이 구간 내 화면 변화가 부족하면 경고한다.

**운영 시 권장**: 방송을 업로드하면 먼저 분당 컷을 재고, 10회 미만이면 "쇼츠 소재로 부적합" 안내를 띄우는 편이 낫다.

## 9. 작업 중 발견해 고친 문제

실제 영상을 넣으면서 드러난 것들이다. 짧은 목데이터에서는 보이지 않았다.

| # | 문제 | 원인 | 대응 |
| --- | --- | --- | --- |
| 1 | STT 큐 하나가 89초 | 진행자가 문장부호 없이 이어 말하고, 발화 뒤 무음이 큐에 붙음 | 무음 1.2초 이상 분할 + 90자 초과 분할 + 무음 꼬리 절단. 큐 중앙값 14.6초 → 1.8초 |
| 2 | 정상 인용을 환각으로 차단 | "차이고요"를 "차고요"로 한 글자 다르게 인용 | 유사도 판정 (0.90↑ 통과 / 0.75↑ WARN / 미만 ERROR) |
| 3 | 정상 자막을 환각으로 차단 | "물기 없이"의 '이'를 숫자 2로 인식 | 자막 검증은 단위가 붙은 수사만 인정 (strict 모드) |
| 4 | 규칙 지킨 모델이 감점 | 기준 구간이 32~140초로 규칙(60~120초)과 불일치 | 기준 재작성 + 재채점 도구. 3.7-flash IoU 0.43 → 0.74 |
| 5 | STT가 부당하게 감점 | 화면 자막에만 있고 발화에 없는 값을 채점 | 채점 키워드에서 제외. kw_score 0.89 → 1.00 |
| 6 | 쇼츠가 멈춰 보임 | 소재 영상 자체가 분당 컷 2.1회 | 움직임 분석 추가, 소재 단계에서 판정 |
